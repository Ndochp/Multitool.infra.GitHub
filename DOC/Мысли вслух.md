# Начало 
(Оно же промт для копилота)
Необходимо разработать архитекутуру по изоляции репозитория программного продукта (1С конфигурации) и инфраструктурной CI обвязки.
Это необходимо, так как 
1.  при пуликации git репозитория с приложением мы не должны зависеть от того, какие средства CI будут у тех, кто форкнет его. Репо с приложением должно содержать только то, что относится непосредственно к приложению - архитектурное описание, код приложения, тесты. 
2. Репозиторий с CI автоматизацией имеет собственный цикл разработки и может быть переиспользован для различных репозиториев 1С конфигураций.

Сценарий использования предполагается следующий: разработчик форкает репозиторий приложения, репозиторий подходящей для его CI инфраструктуры, настраивает переменные окружения на своем Git/CI сервере и получает возможность прогонять необходимые тесты для CI/MR в репозиторий приложения, формировать и публиковать релизные артефакты после обновления мастер ветки.


Для повышения конкретики - пока предполагаеся что репозиторий приложения будет опубликован на гитхаб (Ndochp/multitool), в этом репозиториии - описание архитектуры такого разделения и инфраструктурная часть для CI на GitHubAction с локальным расположением исполнителя.
